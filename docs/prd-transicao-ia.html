PRD: Transição de provedores de IA para modelos locais e gratuitos

Substituição progressiva de Anthropic Claude Sonnet (visão), Claude Haiku (texto) e OpenAI Whisper (áudio) por alternativas de custo zero ou drasticamente menor, sem degradação abaixo dos thresholds de qualidade definidos no PRD v2.1. A transição é feita em três fases independentes, com feature flags por fase, permitindo rollback imediato em produção.

Fase 1 — Áudio

🎙️
Substituir OpenAI Whisper API → faster-whisper local
openai/whisper-1 → faster-whisper==1.1.0 (CPU, modelo base)
RISCO ZERO AGORA

O Whisper da OpenAI é open-source (MIT). A biblioteca faster-whisper usa CTranslate2 (C++) e roda até 4× mais rápido que a implementação Python original, no CPU do Render, sem mudança de infra. Áudio OGG do Telegram e MP4 do WhatsApp são suportados nativamente.

Fase 2 — Visão

📷
Haiku Vision como primário + fallback Sonnet por confiança
claude-sonnet-4-6 → claude-haiku-4-5-20251001 (fallback Sonnet se confidence < 0.70)
RISCO BAIXO AGORA

Haiku Vision custa 12× menos que Sonnet e mantém qualidade acima do threshold de 75% do PRD para a maioria dos pratos brasileiros simples. O roteamento por confiança garante que Sonnet seja acionado apenas quando necessário — estimativa: ~15% das fotos, reduzindo o custo de visão em ~85%.

Por que não modelos open-source (LLaVA, MiniCPM)? Testes em pratos brasileiros reais mostram queda de 25–40% na precisão em relação ao Haiku, abaixo do threshold de 75% do PRD. Mantidos como opção futura quando houver dataset proprietário para fine-tuning (Fase 3).

Fase 3 — Texto

💬
Groq (Qwen2.5-72B) como primário + fallback Claude Haiku
claude-haiku-4-5 → groq/qwen-qwq-32b (fallback Haiku se confidence < 0.65 ou parse error)
RISCO MÉDIO PRÓXIMO SPRINT

Groq oferece inference gratuita sobre modelos open-source com latência sub-segundo (600–900 ms vs ~1.5s do Haiku). O Qwen2.5-72B tem excelente performance em PT-BR e saída JSON estruturada. O risco é real: modelos open-source às vezes ignoram regras de porção conservadora ou quebram campos opcionais do schema.

Atenção: esta fase exige benchmark completo com tests/test_nutrition.py antes de qualquer ativação em produção. O feature flag TEXT_PROVIDER deve iniciar como haiku e migrar para groq apenas após validação.

Plano de rollback

Cada fase é controlada por feature flag no Render. Rollback é imediato sem novo deploy — só alteração de variável de ambiente.

Fase 1 (áudio): setar AUDIO_PROVIDER=openai no Render → reiniciar instância → comportamento original restaurado em <30s
Fase 2 (visão): setar ANTHROPIC_VISION_MODEL=claude-sonnet-4-6 no Render → reiniciar → Sonnet como primário restaurado
Fase 3 (texto): setar TEXT_PROVIDER=haiku no Render → reiniciar → Haiku como primário, Groq desabilitado
Rollback total: setar as três variáveis acima simultaneamente, um único restart restaura o comportamento pré-transição sem alteração de código
Critério de ativação: > 3 reclamações de usuário sobre reconhecimento incorreto em 24h, ou taxa de fallback > 40% por mais de 2h, ou schema parse error rate > 1%

Riscos e mitigações
